# CoopCookingGame

**目前版本:V2.4**

雙人合作手機網頁遊戲,類似《胡鬧廚房》玩法,兩支 iPhone 透過 WebRTC 直連遊玩,不需要 App Store,不需要 Mac,遊戲進行中不需要電腦。

線上網址(GitHub Pages):**https://as5335656.github.io/CoopCookingGame/**

## 版本規則
`VERSION` 檔案跟 `index.html` 選單畫面右下角的版本號要保持一致。**每次推上 GitHub 部署新版本時,都要更新這兩個地方的版本號**,方便之後排查「兩支手機是不是玩到同一版」這類問題。

## 技術棧
- 純前端網頁:HTML5 + Canvas
- 遊戲框架:Phaser.js
- 連線:PeerJS(WebRTC 封裝),用短房號配對,配對完成後雙方直接 P2P 傳資料

## 怎麼玩(開發測試階段)
1. 在電腦上跑本機伺服器:`node dev-server.js`
2. 兩支 iPhone 連到跟電腦同一個 WiFi
3. Safari 開啟 `http://<電腦的區網IP>:3000`
4. 一支按「建立房間」拿到房號,另一支輸入房號「加入房間」

## 角色分工
兩人共用同一個廚房場景,依場景佈局分工(不是程式碼寫死的角色類別):
- 左側:料理站(材料箱、油炸鍋、取盤、垃圾桶、工作台)
- 右側:外場(飲料機、顧客桌位),顧客主要從右側/門口進來
- **中間走道兩邊都不能穿越**,雙方各自鎖在自己的區域,只能靠出餐口交接東西

## 關卡系統
目前先固定開 **8 關(顯示成 1-1 ~ 1-8)**,主選單有一個關卡選擇器(－/＋)。建立房間/加入房間/本機測試/編輯佈局都會用選單當下選到的關卡——**兩支手機要玩同一關,記得先口頭確認選同一個關卡編號**(這點跟房號一樣,目前沒有自動同步機制)。每一關可以有自己的一套菜色(`RecipeData.js` 的 `LEVEL_RECIPE_IDS`),1-1 沒特別設定就沿用預設的薯條+飲料。

### 1-1:漢堡關卡
1-1 換成漢堡系統,6 種成品(牛肉/雞肉 × 原味/吉士/番茄):
- 平底鍋(通用):放生牛肉或生雞肉上去會自動辨識,煮熟後放太久沒收會燒焦(變成焦肉,只能丟垃圾桶)
- 鉆板:切番茄用,生番茄切完變番茄切片
- 生菜/起士/漢堡(麵包)不用加工,材料箱直接拿
- 取盤:空手點一下拿空盤;拿著單一食材點一下,直接連盤子一起拿起來開始組合
- 拿著盤子(組合中)去跟材料箱/平底鍋/鉆板互動,會把東西「加進」盤子裡,不是取代手上的東西;**加進去的東西如果不可能湊出任何一份食譜就會被擋下**(例如生牛肉配起士永遠兜不出食譜,因為食譜認的是熟牛肉不是生牛肉),湊滿某份食譜的食材組合(順序不重要)後,盤子會自動變成那道成品
- 平底鍋/鉆板/取盤三個廚具的圖片本身就畫了檯面,場景裡直接整塊顯示,不會再疊一層色塊底

## 操作方式
- **只能點物件移動**(不是搖桿,點空地沒有反應),點到站點會自動走過去、靠近到可互動距離就會自動觸發互動
- **角色跟角色、角色跟站點都不能重疊**,撞到會卡在邊緣(因為有這層碰撞,角色實際上不會走到物件正中心,所以「抵達」的判定是「靠近到可互動距離內」,不是走到正中心)
- 一般連線模式:手機各自只控制自己的角色
- **本機測試模式**(選單「本機測試」按鈕):不用連線,一個人在同一台裝置上同時操控 P1(點左半邊)和 P2(點右半邊),方便自己一人測試玩法
- **編輯佈局模式**(選單「編輯佈局」按鈕):會編輯選單當下選到的那一關。進入後遊戲模擬(訂單/顧客/計時)是暫停的,不會有顧客。
  - 拖拉物件可以調整位置(物件之間不會互相重疊,撞到會卡在邊緣)
  - **新增廚具要先放「桌子/檯面」當地基**:面板第一個按鈕是桌子,點了會直接生成一張空桌;其他種類(材料箱、鍋具、鉆板...)點下去是「選取」該種類(按鈕會反白),接著點場景裡一張空桌子,就會把選好的廚具放上去、變成那個廚具(桌子本身消失,直接變成那個廚具站點);再點一次同一個面板按鈕可以取消選取
  - **調整大小**:直接點場景裡任一個物件,面板會顯示那個物件的種類,再用 －/＋ 調整「那個種類全部物件」的大小(不是只調整點到的那一個)
  - **刪除模式**:按「刪除模式:關閉」切換成開啟,開啟後點任何物件會直接刪掉它;再點一次按鈕關閉刪除模式,恢復正常操作
  - 編輯結果會自動存在這台裝置的瀏覽器裡(`localStorage`,依關卡分開存,重新整理/下次進來都會沿用),但**不會同步到別的裝置**;要讓兩支手機都拿到同一份佈局,還是要按「複製佈局」把結果複製起來貼給開發者,寫進程式碼正式部署。想丟掉目前這一關存的、換回程式碼內建的預設佈局,按「還原成預設佈局」即可

## 快取問題
每次部署新版本,`index.html`、CSS/JS 檔案、美術素材網址都會加上 `?v=版本號` 的參數,手機瀏覽器會自動抓最新版本,不用手動清快取。**每次改版都要記得同步更新這個版本號**(`index.html` 裡的 script/link 標籤、`KitchenScene.js` 的 `preload()`),不然還是可能卡到舊圖。

## 美術素材
- 角色:P1(貓)、P2(熊)都是真正的 PNG 圖(已去背,背景透明),依移動方向切換左右圖(`assets/sprites/p1_left.png` / `p1_right.png` / `p1_idle.png`,P2 同理),靜止時顯示 idle 圖
- 桌子:使用者提供的木紋桌面圖(`assets/sprites/table.png`)
- 背景:使用者提供的磁磚花紋圖(`assets/sprites/background.png`)
- 其餘站點(廚具、出餐口等)仍是方形色塊 + emoji 佔位,不顯示名稱文字
等使用者提供更多正式 PNG 後,只需要在 `KitchenScene.js` 把對應的 emoji Text 物件換成 Phaser Image/Sprite 即可,不影響其他邏輯。
建議:透明背景、英文命名、同類型素材尺寸盡量一致。

## 已知限制
- Host(建立房間的那支手機)的瀏覽器分頁在遊戲中不能被切到背景或關閉,否則遊戲邏輯會停止(P2P 架構的取捨)
- 配對當下手機需要能連上網路(PeerJS 免費公開訊號伺服器),配對成功後遊戲資料才是純手機對手機直傳
- 目前只有 1 關(1-1)有客製化佈局,固定 3 分鐘、2 道菜色(薯條、飲料)
- 如果某一關的站點擺得很密集,角色可能會被夾在縫隙間走不過去;這種情況下角色卡住超過 2.5 秒會直接放行抵達目標,確保一定能互動成功(代價是那一小段路徑看起來像穿過了障礙物)

## 畫面解析度(HiDPI)
Phaser 預設不會自動處理手機的高解析度螢幕,直接用 960x540 畫布會在螢幕上被放大顯示,看起來模糊。
做法:`main.js` 建立遊戲時把畫布實際像素尺寸乘上 `devicePixelRatio`,`KitchenScene.js` 的 `create()` 再用 camera `setZoom(dpr)` + `centerOn(邏輯世界中心)` 把視角縮放/置中回邏輯座標——所有站點/玩家的座標完全不用改,只有畫面變清晰。
